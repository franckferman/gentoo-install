gentoo-install

A modular Gentoo installer in bash: ten numbered steps, a signed stage3, and a plan you can read before anything is written.

Status: 0.1.0. One machine has been installed by this script and booted. A disk image went from an empty GPT to a login prompt — unencrypted, GRUB on UEFI, the distribution kernel — and was then started under QEMU with OVMF firmware, where the account the installer created logged in and escalated with sudo.

What that does not cover: nothing encrypted has been carried through to a machine that asks for a passphrase at power-on, and neither efistub nor systemd-boot has been booted. Read the plan before you point version 0.1.0 at a disk you would miss.

What it is

An installer for Gentoo on amd64, written as ten numbered steps that can be run together, selected individually, or resumed after an interruption. The step number is the public API and does not change.

It fetches a stage3 through a signature chain rather than a checksum, keeps every setting in one place where a file, a flag and a profile all reach it under a stated precedence, and refuses a disk that carries the running system, is mounted, or is removable — each refusal with its own switch, never one blanket flag. The confirmation for erasing a disk is the device path typed out; neither --yes nor --force lifts it.

# the plan, on this machine, changing nothing — no root needed
./gentoo-install.sh --dry-run

The ten steps

Each one runs alone, in a range, or resumed after an interruption. The number is the API: --steps 20,40-60 means what it says, and the numbering does not shift when a step is added between two others.

  1. 10 pre-flight: privileges, tools, network, disk inventory
  2. 20 partition and format the target disks — the destructive one
  3. 30 LUKS containers and keyfiles
  4. 40 fetch, verify and unpack the stage3 tarball
  5. 50 mount the pseudo-filesystems and enter the chroot
  6. 60 portage: make.conf, repositories, profile, USE flags
  7. 70 kernel sources, configuration and build
  8. 80 bootloader install and entries
  9. 90 system: fstab, locale, timezone, network, users, packages
  10. 95 finalize: verify, unmount, report what to do next

The choices

Encryption

  • luks-passphrase — default
  • luks-tpm
  • luks-keyfile-gpg
  • none

Bootloader

  • grub — default, boots everywhere
  • efistub
  • systemd-boot

Kernel

  • dist-kernel — default
  • genkernel
  • manual

Disk layout

  • minimal — one root, no LVM
  • server — /var and /var/log split
  • desktop — default, /home takes the rest
  • custom

Also in the repository

Ten standalone rescue scripts for a machine that is already installed and no longer boots: LUKS diagnostics, unlocking and chrooting from a live medium, keyslot and header management, TPM inspection and resealing, and a firmware update that proves it can be survived before it runs. None of them sources a library, so any one can be copied alone onto a USB stick.
